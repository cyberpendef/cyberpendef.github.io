# CyberPenDef Website

The CyberPenDef website is a static Hugo site for IT support and cybersecurity consultancy. The frontend uses Hugo templates, Markdown/YAML content, custom CSS, and small amounts of browser-side JavaScript. It is hosted on GitHub Pages and uses external services only for features that need them.

**Live site:** <https://cyberpendef.github.io/>

## Technology at a glance

| Area | Current technology |
| --- | --- |
| Site generation | Hugo Extended |
| Frontend | Hugo templates, HTML, CSS, and Vanilla JavaScript |
| Hosting and deployment | GitHub Pages with GitHub Actions |
| Content editing | Decap CMS, backed by this GitHub repository |
| Inquiry form and client features | Supabase Edge Functions and PostgreSQL |
| Bot verification | Cloudflare Turnstile |
| CMS OAuth | Cloudflare Worker |
| Booking | Cal.com embed |

The public pages are generated as static files. Supabase functions provide server-side behavior for features such as inquiry submissions and the AI assistant. Keep backend secrets in the relevant provider’s secret settings; do not add them to frontend files or commit them.

## Edit website content

### Through Decap CMS

Open <https://cyberpendef.github.io/admin/> and sign in through the configured GitHub OAuth flow. CMS changes are committed to the repository; publishing them triggers the GitHub Pages workflow.

- **Services and categories:** edit the **Service Catalog** collection. Service text and tags are stored in [`data/services.yaml`](./data/services.yaml). Existing illustrations are code-managed; select **Generic** when creating a service without a matching illustration.
- **Homepage sections:** edit the **Home Page Content** collection in [`data/home.yaml`](./data/home.yaml). It controls the hero, promotion, edge cards, overview, audience, credentials, and closing call to action.
- **About page:** edit the page title fields under **Site Pages**, and edit introduction, approach, credentials, values, and the closing quote under **About Profile** in [`data/about.yaml`](./data/about.yaml).
- **Contact page copy:** edit the **Contact Page Content** collection in [`data/contact.yaml`](./data/contact.yaml). It controls the hero, inquiry form labels and select options, contact channels, business hours, and delivery information. The form integration, Turnstile widget, and booking implementation remain code-managed.
- **Client portal copy:** edit the **Client Portal Content** collection in [`data/portal.yaml`](./data/portal.yaml). It controls login, signup, and dashboard labels and messages. Authentication, route protection, Supabase access, and ticket rendering remain code-managed.
- **CMS authentication:** use the deployed admin at <https://cyberpendef.github.io/admin/> for GitHub OAuth and publishing. The shared Decap config must not enable the local proxy; local proxy mode is only for uncommitted development configuration.
- **Blog and portfolio:** use their respective CMS collections. Entries are stored under `content/blog/` and `content/portfolio/`.
- **Other site pages:** available page fields are configured under **Site Pages** in [`static/admin/config.yml`](./static/admin/config.yml).

### In the repository

For direct edits, use the source files:

- Service catalog content: [`data/services.yaml`](./data/services.yaml)
- Homepage sections: [`data/home.yaml`](./data/home.yaml)
- Contact page sections: [`data/contact.yaml`](./data/contact.yaml)
- Client portal copy: [`data/portal.yaml`](./data/portal.yaml)
- Services page hero: [`content/services/_index.md`](./content/services/_index.md)
- About page profile: [`data/about.yaml`](./data/about.yaml)
- About page title fields: [`content/about/_index.md`](./content/about/_index.md)
- Shared styles: [`assets/css/main.css`](./assets/css/main.css)
- Page templates and reusable components: [`layouts/`](./layouts/)

When adding a service directly to the YAML catalog, use an existing illustration ID or `generic`. Add new illustration templates under `layouts/partials/services/illustrations/` and expose their IDs in the CMS illustration selector in `static/admin/config.yml`.

## Run and build locally

Install Hugo Extended, then run a local preview from the repository root:

```sh
hugo server
```

Open the local URL printed by Hugo, usually <http://localhost:1313/>.

Build the production site without replacing the repository’s generated `public/` directory:

```sh
hugo --minify --destination /tmp/cyberpendef-site-build
```

The Hugo build does not require an npm-based frontend bundler.

## Deployment

The workflow in [`.github/workflows/hugo.yml`](./.github/workflows/hugo.yml) builds the site with Hugo and deploys the generated `public/` directory to GitHub Pages when changes are pushed to `main`. Check the repository’s **Actions** tab if a deployment does not complete.

## Security and external services

- The browser may contain public configuration such as a Supabase URL or anon key; public values are not substitutes for database Row Level Security.
- Keep service-role, email-provider, AI-provider, OAuth, and Turnstile secret keys in their server-side provider settings.
- Verify Turnstile tokens in the corresponding Edge Function; client-side challenges alone are not an authorization control.
- Review database access policies in `supabase/schema.sql` before changing data access.
- Changes to third-party providers, free-tier quotas, or hosting plans may affect cost and availability. Confirm current provider terms in their dashboards.
